# 薪跳维护规则

## 用户已确认的工作流

- 本项目位于 `x2781954452/web-project_small-Created-by-XZJ` 仓库的 `xintiao/` 目录。
- 用户授权：对薪跳完成修改及必要验证后，同步源码到这个 GitHub 仓库。
- 用户要求：先保存 GitHub；只有用户随后明确确认发布，才更新 Cloudflare。上传 GitHub、修改完成或测试通过都不等于获准发布。
- 未获确认时，不部署、不连接自动发布、不更新会触发生产/预览部署的分支，也不新建 Cloudflare 站点。
- 若未来仓库已有自动发布、预览或工作流，推送前先检查触发规则；不能让“同步源码”提前触发上线或收费任务。
- 不将其他项目一并改动或同步，不改变仓库可见性。

## 开发与发布

- 网页源码位于 `dist/`；纯 HTML/CSS/JavaScript，无构建步骤。沿用用户现有产品名称和界面，除非用户要求改名。
- 修改前获取 GitHub 最新版本；保留用户未提交改动，避免用过期本地副本覆盖远程更新。
- 现有 Cloudflare 项目 `shixin-time` 使用 Direct Upload，线上地址 https://shixin-time.pages.dev/ 。保留现有项目和地址。
- 使用 github-cloudflare-release 技能（如可用）检查发布费用与限制；该技能不覆盖本文件更明确的“用户确认后才发布”要求。
- 不上传凭据、浏览器 localStorage、用户实际工资或其他私人数据。
- `release-state.json` 的最后部署信息不能在仅同步代码时冒充最新线上版本。

## 汇报

每次明确说明修改内容、验证结果、GitHub 提交，以及 Cloudflare 是“未更新”还是“已获授权并发布”。本规则由执行任务的 agent 按需落实，不是文件监控或后台自动同步程序。
